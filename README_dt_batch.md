# Пакетный анализ Digital Twin v6.2 — `dt_batch.py`

Прогоняет полный цикл `run_pipeline_extended()` из `ivf_digital_twin.py` для каждой
пациентки из Excel-выгрузки клиники (формат «отчет.xlsx») и формирует три файла.

## Что подаётся в модель («форма» DT)

Ровно 4 значения — остальное идёт в аналитику, но НЕ в модель:

| Поле формы DT | Колонка выгрузки | Назначение |
|---|---|---|
| `PatientInput.female_age` | `Возраст` | возраст |
| `follicles` (N follicles OPU) | `Количество фолликулов` | фолликулы на пункции |
| `KnownValues.okk` | `Число ОКК` | получено ооцитов |
| `KnownValues.mii` | `Число инсеминированных` | по указанию автора модели |

- **АМГ / КАФ** есть в выгрузке, но «часто некорректны» → по умолчанию в модель
  НЕ подаются (берутся референсные `amh=2.0`, `afc=12`). Реальные АМГ/КАФ при этом
  сохраняются в выходные файлы. Чтобы подавать их в модель — поставьте
  `USE_REPORT_AMH_AFC = True` (с проверкой на правдоподобие).
- **BMI** в выгрузке нет → дефолт `23.0` (`DEFAULT_BMI`).
- **2pN, бластоцисты, хор.кач., исход** в модель НЕ подаются — они прогнозируются
  и затем сравниваются с фактом (предиктивная валидация).

## Выходные файлы

1. **`dt_predictions.csv`** — 66 колонок, схема 1-в-1 с `_save_analytics()` из `app.py`
   (медианы и перцентили воронки, `p_per_transfer`, `p_overall_cycle`, байес-posterior,
   NVSA, кластер L4, OHSS, Esteves-банкинг). Колонки `p_csdi*` и L6/GNN пустые —
   ровно как само приложение оставляет их, пока не открыты вкладки Diffusion/GNN.
   Колонки нейросети (`p_kat_raw`, `p_nvsa`) заполняются прокси FORTUNE+KPI, т.к.
   веса KAN/FT/KAT не загружены (см. ниже).
2. **`OPU_table_filled.xlsx`** — формат OPU_table: реальные данные пациенток +
   колонка `DIGITAL TWIN` (headline-прогноз = вероятность беременности за цикл).
3. **`dt_vs_real_comparison.csv`** — прогноз DT против факта по каждой стадии
   воронки и по исходу беременности (удобно для оценки согласованности).

## Запуск

```bash
python dt_batch.py <input.xlsx> [output_dir]
# модули src/ должны быть рядом, либо укажите путь:
DT_SRC_DIR=/путь/к/src python dt_batch.py real_export.xlsx ./out
```

## Слои моделей: что активно

- **L1 воронка (ZINB), L2 FORTUNE+KPI, L4 кластер, байес, Esteves** — работают на
  чистом numpy/scipy, файлы моделей не нужны. ✅
- **L3 нейросеть (KAN/FT/KAT)** — нужны веса `Prediction_KAN.pth`,
  `FTTransformer.joblib`, `KAT_calibrated_model.pkl` (+ `torch`). Без них стадия
  честно откатывается на FORTUNE+KPI (поле `nn_prediction.source` это помечает).
- **L5 CSDI, L6 GNN** — отдельные вкладки приложения, в пакетный расчёт не входят.

Если нужно включить L3 в пакет — загрузите три файла весов (или их `.enc`-версии);
тогда `dt_predictions.csv` получит реальные `p_kat_raw` / `p_nvsa` от нейросети.

## Конфиг (вверху `dt_batch.py`)

`N_SIM`, `DEFAULT_BMI`, `USE_REPORT_AMH_AFC`, `DEFAULT_AMH/AFC`, `SPERM_SOURCE`,
`CLINIC_SUCCESSES/TRIALS` (реальные батчи клиники для байес-prior), `DT_HEADLINE`.

> Файлы с пометкой `_DEMO` получены на синтетических 12 пациентках (реальная
> выгрузка на ~100 пациенток ещё не загружена). Формат идентичен боевому.
