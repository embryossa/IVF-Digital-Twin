# Нарратор IVF Digital Twin на локальной gemma4:12b — отчёт по тестированию

Дата прогона: 26.07.2026. Стенд: `narrator_qa/` (описание — `PIPELINE.md`).
Исходный код обоих проектов не изменялся.

## Условия

| | |
|---|---|
| CPU | Intel i7-8665U, 4 ядра / 8 потоков, 1.9 ГГц (мобильный ULV, 2019) |
| RAM | 31.8 ГБ |
| GPU | Intel UHD 620 — не используется, инференс 100% на CPU |
| Ollama | 0.32.4, контекст слота 8192 |
| Модель | `gemma4:12b-it-qat`, Q4_0, 8.8 ГБ резидентно |
| Параметры | temperature 0.35 (из проекта), think=False, `/no_think` |

Измеренная пропускная способность:

| операция | скорость | стоимость токена |
|---|---:|---:|
| обработка промпта (prompt eval) | 5.7–6.2 ток/с | **0.174 с** |
| генерация (token generation) | 2.0–2.2 ток/с | **0.465 с** |

Это не настройка, а физика: 12B в Q4_0 — это ~7 ГБ весов, которые нужно
прочитать из памяти на каждый токен; двухканальный DDR4 такого ноутбука даёт
потолок в районе 3 ток/с. Ускорить это конфигурацией нельзя — можно только
сократить число токенов или взять модель поменьше.

## Бюджет времени на одну пациентку

| конфигурация | промпт | выход | итого |
|---|---:|---:|---:|
| полный нарратив, 9 разделов (измерено) | 3066 ток → 8.2 мин | 1262 ток → 10.5 мин | **18.7 мин** |
| concise (измерено) | 3040 ток → 8.5 мин | 431 ток → 3.4 мин | **11.9 мин** |
| concise + сжатый контекст (расчёт) | ~2250 ток → 6.5 мин | 431 ток → 3.4 мин | **~9.9 мин** |
| повтор пациента, кэш llama.cpp (измерено) | снимок → 1.4 с | 431 ток → 3.4 мин | **3.5 мин** |
| повтор пациента, `llm_cache.py` (продакшн) | — | текст с диска | **мгновенно** |

Два механизма повтора не надо путать. `llm_cache.py` хэширует контекст и отдаёт
**ранее сгенерированный текст**, вообще не обращаясь к модели — в приложении
повторное открытие пациентки бесплатно. Снимок состояния в llama.cpp экономит
только обработку промпта (1.4 с вместо ≈490 с), генерация всё равно выполняется;
это то, что видно в стенде, где дисковый кэш намеренно обойдён.

Вывод по производительности: **на этом железе gemma4:12b пригодна для отложенного
разбора, но не для приёма.** Первое открытие карты — 12–19 минут.

цифр. Единственный дефект, встречающийся почти всегда, — **утечки сырых ключей
(7 из 8 прогонов, от 2 до 8 штук)**. Остальные эпизодичны: по 1–2 случая.

### Отдельно: обработка дозы и гайдлайнов

Там, где нарратор доходит до раздела протокола, он делает это безошибочно:

| сценарий | номограмма | что написано |
|---|---|---|
| S01 | [100, 150] | «сниженной стартовой дозой… в диапазоне **100–150 МЕ** (согласно номограмме)» |
| S02 | [225, 300] | «стартовой дозой в диапазоне **225–300 МЕ**» |
| S03 | [150, 225] | «ориентира по номограмме… стартовую дозу в диапазоне **150–225 МЕ**» |

Три из трёх — полный диапазон, точное совпадение, правильная рамка «ориентир»,
ни одного изобретённого числа. Там, где блока протокола нет (S07, S11), доза не
упоминается вовсе.

Проблема в другом — в частоте. `protocol_guidance` присутствовал в контексте в
6 сценариях, а раздел появился в тексте в **3**; ссылки на источники — в двух
(S03 — шесть, S02 — одна). Блок стоит ~1050 токенов ≈ 3 минуты на каждой
пациентке. То есть самый дорогой компонент промпта в быстром режиме доходит до
врача примерно в половине случаев.

## Разбор находок

### Главный вывод

Разделение труда в DT («Python классифицирует — LLM объясняет») работает по
своему прямому назначению: **числовая заземлённость безупречна — 1.00 во всех
прогонах, ни одного выдуманного числа, ни одной дозы вне номограммы.** Это
сильный результат для 12B-модели на 4-битном кванте.

Ломается не арифметика, а **семантика**: единицы измерения, направление
категории, причинно-следственные связи и границы того, о чём вообще есть данные.
И — что важнее всего для приоритезации — **бо́льшая часть найденных дефектов
приходит не из модели, а из контекста, который ей передают.** Модель честно
объясняет то, что ей дали; если ей дали грейд «B» без единого доказательства,
она напишет «модель демонстрирует стабильность».

### Что нарратор делает надёжно

- Не изобретает чисел (`grnd = 1.00` во всех прогонах).
- Не переклассифицирует главный прогноз: `level: low` при оптимистичных
  GAT-соседях остаётся `low`.
- Дозу берёт только из номограммы (`faithfulness: ok` везде).
- Держит грейд C и OOD-статус, не смягчая их.
- В разреженном контексте не выдумывает дозу, гайдлайны и GAT-аналоги.

### Что ломается

**1. Единицы измерения (S02).** `banking_mii.euploids_expected: 0.1` — это
ожидаемое *число* эуплоидных бластоцист. В тексте: «крайне низкая **вероятность**
получения эуплоидных эмбрионов (**0.1%**)». Причина — имена полей несут единицу
только для процентов (`P_pct`), а счётчики идут голым числом; текстовые
`пояснение`, которые были в старом `build_clinical_context`, при переходе на
компактный контекст выпали.

**2. Направление категории (S04).** `agreement: moderate_model_agreement`
(разброс 24.3 пп) пересказано как «**несогласием моделей**» — прямо рядом с
процитированной в скобках противоположной меткой.

**3. Выдуманная причинность (S04).** «Конфидентность уровня C обусловлена…
несогласием моделей». На самом деле грейд C выставлен ветвью двойного OOD.
Пре-классификатор знает причину, но наружу отдаёт только букву — нарратор
достраивает объяснение сам.

**4. Раздел без данных (S07).** Блока `banking_mii` в контексте нет; раздел
«Банкинг MII» написан. Чисел в нём нет, поэтому формально правила не нарушены,
но у врача создаётся впечатление выполненного расчёта. Спровоцировано
статическим `_QUESTION_CONCISE`, который просит банкинг всегда.

**5. Сырые ключи JSON в клиническом тексте (все прогоны, 2–7 штук).**
«Ключевой риск — высокая вероятность отмены (**P_cancel_pct: 21.2%**)…
стратегия «**extended_accumulation**»… при высоком согласии моделей
(**high_model_agreement**)». Текст читается как отладочный дамп.

**6. Директивный глагол (S01).** «**Рекомендуется** рассмотреть
антагонист-протокол» — правило 3 системного промпта прямо это запрещает.
Модель оказывается между двумя инструкциями: собственный текст извлечённых
гайдлайнов написан именно директивно («рекомендуется рассмотреть…»).

**7. Цитаты в круглых скобках.** «(J Assist Reprod Genet 2021)» — и штатный
`faithfulness.py`, который ищет только квадратные скобки, эти ссылки **не
проверяет вообще**, возвращая `ok`.

**8. Раздел аналогов молча выпадает (S01, S02, S09 — 3 из 3).** GAT-соседи в
контексте есть, в concise-режиме модель их пропускает. В S09 это скрыло от врача
расхождение втрое между BEFE (22.1%) и медианой аналогов (61%).

**9. Введение клинической темы, которой нет в контексте (S11).** «Основное
внимание стоит уделить **качеству ПГТ-А**, так как вероятность отсутствия
бластоцист составляет 11.1%». ПГТ-А в контексте S11 не фигурирует, и связь с
вероятностью отсутствия бластоцист не следует из данных. Показательно, что
**ни одна детерминированная метрика этого не ловит**: число подлинное, категория
не перевёрнута, дозы нет. Такие случаи находит только чтение человеком — поэтому
стенд намеренно не претендует на полную автоматизацию оценки.

### Качество формулировок — отдельно от соблюдения правил

Оценка по прочитанным текстам (метрики этого не измеряют).

**Что получается хорошо.**
- *Регистр выбран верно.* Текст обращён к коллеге-врачу, без упрощений «для
  пациента» и без псевдонаучного утяжеления. Термины BEFE, MII, СГЯ, ПГТ-А
  используются свободно и к месту.
- *Терминология корректна.* За семь прогонов не встретилось ни одного неверного
  употребления репродуктологического термина.
- *Иногда появляется настоящая интерпретация,* а не пересказ: «Доверительный
  интервал (37.1–50.2%) достаточно узок, что позволяет говорить о стабильности
  прогноза для данного профиля» — это именно то, чего ждут от нарратора.
- *Сжатие работает.* В concise-режиме 140–210 слов несут почти всю
  клинически значимую информацию.

**Что получается плохо.**
- *Канцелярит.* «В связи с этим», «Данный подход», «Ключевым аспектом данного
  случая является», «что требует взвешенного подхода к планированию стратегии».
  Причина установлена: подробный стилевой регламент `SYSTEM_NARRATOR_v2.md`
  (15.8 КБ, с парами «плохо/хорошо») **не подключён к коду** — продакшн
  использует короткий промпт v3, где указаний по стилю нет вообще.
- *Разделы не связаны между собой.* Каждый абзац самодостаточен, сквозной
  аргумент не строится. Для сравнения, `lead-analyst` в аналитическом проекте
  ведёт одну линию через весь разбор («рассказывает четырьмя независимыми
  способами, которые сходятся в одной точке»). Локальный нарратор выдаёт
  список фактов, а не объяснение.
- *Пересказ вместо смысла.* Значительная доля предложений — это число плюс
  ярлык: «Риск СГЯ оценивается как низкий (P_mod: 5.1%, P_sev: 0.9%)».
  Клинического «и что это значит для этой пациентки» часто нет.
- *Склейка готовых формулировок.* Поля `management` подаются уже написанными
  фразами, и модель соединяет их без согласования: «обсудить это с пациенткой
  заранее стоит учитывать как приоритет» (S04).

**Общая оценка.** Как исполнитель жёсткого контракта — хорошо: правила
соблюдает, числа не выдумывает. Как автор клинического текста — на уровне
аккуратного, но формального протокола: читаемо и безопасно, но не объясняет.
Разрыв с `lead-analyst` (Opus) здесь принципиальный и моделью 12B на CPU
не закрывается — но существенная часть разрыва объясняется не размером модели,
а тем, что стилевая спецификация просто не доехала до промпта.

### Что при этом важно не потерять

Нарратор ни разу не нарушил главные клинические ограничители: не поставил
диагноз, не назначил лечение, не занизил и не завысил уровень прогноза, не
вывел дозу за пределы номограммы. Проблемы, перечисленные выше, — это проблемы
точности изложения и качества контракта с контекстом, а не потеря контроля над
моделью.
